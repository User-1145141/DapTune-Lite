# ADR 0002：按 DAP 回读能力选择写入事务

- 状态：已采纳
- 日期：2026-08-10

## 决策

一次应用曲线先按 effect descriptor 判断协议能力，而不是按手机型号或固件版本分支：

1. 检查 descriptor、控制权、effect/DAP 开关和 profile 数量。
2. 代理型 `DAP`（type `fa81dbde-588b-11ed-9b6a-0242ac120002`）支持参数 110 回读：读取并暂存所有
   profile，写入同一条 20 段 Q4 曲线，逐个完整数组比较，全部一致后保存；任一不一致或异常则恢复原数组。
3. 直连型 `DAP_offload`（type `46d279d9-9be7-453d-9d7c-ef937f675587`）是 setter-only：直接写入
   全部 profile 并保存，再复核控制权、开关、profile 数量和当前 profile。它不执行曲线回读，也绝不把返回的
   零填充缓冲区当作真实曲线或回滚依据。
4. 未识别的 descriptor 保守地按 setter-only 处理，避免伪回读造成破坏性回滚。

所有 DAP 操作由进程内互斥锁串行化，并在 `finally` 中释放 `AudioEffect`。应用不切换 Dolby，不写入
其他参数。持久化状态明确区分“曲线已回读验证”和“写入命令已接受”；后者不会伪装成已验证。

## 原因

小米系统根据当前输出和场景选择不同 Dolby profile，因此必须写入全部 profile。实机对照表明，代理型
`DAP` 能回读真实曲线，而直连 `DAP_offload` 对同一读取请求只返回固定长度的全零缓冲区；此前把它当成
真实回读会导致非零写入被判失败并立即回滚为零。能力分级保留了可回读设备的强事务保证，也让 setter-only
设备遵循厂商设置应用使用的真实写入语义。
