# ADR 0002：DAP 写入必须是可回滚事务

- 状态：已采纳
- 日期：2026-08-10

## 决策

一次应用曲线按以下顺序执行：

1. 检查 descriptor、控制权、effect/DAP 开关和 profile 数量。
2. 读取并暂存所有 profile 的参数 110。
3. 向每个 profile 写入同一条 20 段 Q4 曲线。
4. 逐个 profile 回读并做完整数组比较。
5. 全部一致后发送保存命令；任一不一致或异常则回写原始数组并保存。

所有 DAP 操作由进程内互斥锁串行化，并在 `finally` 中释放 `AudioEffect`。应用不切换 Dolby，不写入
其他参数，也不尝试绕过 ±10 dB 的设备约束。

## 原因

小米系统根据当前输出和场景选择不同 Dolby profile。只写当前 profile 会造成设备切换后曲线失效；
先保存再验证又可能留下部分写入状态。读前备份、写后验证和失败回滚可将风险限制在一次事务内。
