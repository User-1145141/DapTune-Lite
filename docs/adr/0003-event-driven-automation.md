# ADR 0003：自动切换采用事件驱动前台服务

- 状态：已采纳
- 日期：2026-08-10

## 决策

自动切换仅在用户显式开启后运行前台服务。服务监听 `AudioDeviceCallback`、`MediaRouter2`、USB/耳机
广播；路由稳定 400 ms 后解析精确设备绑定、设备类型绑定和默认配置。小米杜比状态广播由同一服务
单独监听，用于强制重新应用当前曲线。相同路由和相同曲线在一次服务生命周期内不重复写入。

平台事件被共享为进程内唯一、无占位初值的路由源，所有页面与服务共用一套系统回调。每次服务启动或
恢复都替换自身唯一的消费会话，不用额外的就绪标记或世代状态猜测回调是否存活。事件源先注册平台回调，
再在带合并缓冲的下游执行数据库查询和 DAP 写入；慢操作期间只保留最新路由。平台注册异常按 1–30 秒
退避恢复并通知服务记录，诊断日志本身不参与监听生命周期。

蓝牙/USB 身份使用 SHA-256 截断摘要形成本地稳定键，原始蓝牙地址不写入数据库。扬声器和有线耳机
使用固定可移植键。服务不轮询、不持有唤醒锁、不进入音频数据路径。

服务使用 Android 的 `START_STICKY` 作为进程被回收后的唯一恢复路径。系统以空 Intent 重建服务时，
服务先进入前台，再读取持久化的自动切换状态：开启时重建唯一消费会话并立即核对当前输出，关闭时自行
停止。显式启动会取消尚未完成的恢复读取，命令世代保证过期结果不能覆盖后续操作。实现不依赖 Activity
生命周期、Alarm、`onTaskRemoved`、周期任务、第二进程或重复的静态路由广播接收器。

## 原因

事件驱动方案的空闲开销接近零，也避免定时轮询在系统后台限制下的不确定性。前台服务为长期设备监听
提供明确的用户可见性和生命周期；杜比状态广播用于在系统音效页覆盖或重新开启后恢复曲线。
