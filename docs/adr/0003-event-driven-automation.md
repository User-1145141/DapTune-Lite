# ADR 0003：自动切换采用事件驱动前台服务

- 状态：已采纳
- 日期：2026-08-10

## 决策

自动切换仅在用户显式开启后运行前台服务。服务监听 `AudioDeviceCallback`、`MediaRouter2`、USB/耳机
广播和小米杜比状态广播；路由稳定 400 ms 后解析精确设备绑定、设备类型绑定和默认配置。相同路由和
相同曲线在一次服务生命周期内不重复写入。

蓝牙/USB 身份使用 SHA-256 截断摘要形成本地稳定键，原始蓝牙地址不写入数据库。扬声器和有线耳机
使用固定可移植键。服务不轮询、不持有唤醒锁、不进入音频数据路径。

服务使用 `START_NOT_STICKY`，不依赖系统的粘性重启。界面离开前只登记一次由系统持有的短延时恢复请求，
界面恢复时立即撤销；这是最近任务卡片被移除后的唯一恢复路径。实现不使用 `onTaskRemoved`、周期任务、
第二进程或重复的静态路由广播接收器。

## 原因

事件驱动方案的空闲开销接近零，也避免定时轮询在系统后台限制下的不确定性。前台服务为长期设备监听
提供明确的用户可见性和生命周期；杜比状态广播用于在系统音效页覆盖或重新开启后恢复曲线。
